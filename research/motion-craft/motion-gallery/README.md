# Motion gallery

The motion styles the direction step offers: each one rendered once as a 3 s loop on a neutral sample. Open `index.html` to browse them by family, energy and tier. Each folder holds `frame.html` (the composition), `preview.mp4`, `poster.jpg` and `meta.json`.

## What the sources' own code gets wrong (found while building)

### The technique library (tiers 2 and 3)

The three biggest problems, each seen across every family:

1. **Nothing is seek-safe.** Canvas and SVG techniques draw only from an `onUpdate` on a proxy tween (every canvas source, the chart races, the counters, the scramble, the camera fly-throughs); discrete states are chains of `tl.set` at absolute times (glitch slices, caption swaps, typing); first tweens are bare `.to` with the from-state living in CSS; `visibility`, `display` and `autoAlpha` do the hard cuts; `tl.call` and relative `-=` positions appear in the planned snippets. HyperFrames seeks with events suppressed, so none of this repaints on a cold seek. Every one was rebuilt as a pure `renderAt(t)` with the `tl.render` wrap, or as `fromTo` with explicit from-states and one-frame opacity cuts.
2. **The harness is load-bearing and non-portable.** Every source depends on `lib/stage.css` tokens (`var(--verm)`, `var(--ink3)`, which GSAP cannot interpolate), serif/didone/mono web fonts whose metrics the geometry relies on (`giant-mask-reveal` hard-codes a mask origin inside a Bodoni stroke; `particle-assemble` and `kinetic-type-sweep` gate the timeline on `document.fonts.load`), `Motion.timeline()` defaults (`power3.out`, 0.6 s) that tweens silently inherit, `Motion.rand` seeds, Korean `.lead` annotations and the folio/caption chrome. The `runtime` field is often wrong (`fluted-glass` is canvas 2D not WebGL, `ink-bleed` is canvas not SVG, `text-echo-trail` is canvas not GSAP, several `css` entries are GSAP in the demo while the snippet is `@keyframes`), so a user copying the snippet gets something different from the clip.
3. **Layout tweens and static CSS transforms on tweened elements.** Bars, panels and labels are animated through `width`, `height`, `left`, `top` or `position` (`layout-reflow`, `accordion-expand`, `state-transition-walk`, `active-indicator-glide`, the SVG charts via style), and many elements carry a CSS `transform` (`translate(-50%,-50%)`, `scaleX(0)`, `scale(.25)`) that GSAP then also tweens (`next-token`, `progressive-disclosure`, `char-stagger`, `kinetic-type-sweep`, `spring-overshoot`, `motion-hierarchy`, `match-cut`, `scroll-scrub-cinema`, `infinite-zoom`): the `gsap_css_transform_conflict` lint error in every such case. Rebuilt as scale/translate with `transformOrigin`, clip-path, or SVG `attr` tweens.

Also systematic: full-frame overlays start visible and are hidden by `tl.set` at 0 (`gsap_fullscreen_overlay_starts_visible`); overlapping scenes carry no overlap allowance so `check` flags `content_overlap` / `text_occluded` (fixed with `data-layout-allow-overlap` / `-occlusion` on the covered text nodes, which must be set per node); SVG `marker-end` arrowheads show before a dash-drawn line arrives; `strokeDasharray = strokeDashoffset = length` leaves a cap dot on frame 0; two `fromTo`s on one property both immediate-render so the later from-state wins at t = 0 (needs `immediateRender: false`, the library's `forEach` loop pattern invites it); `grid-flip` inlines 96 copies of both scenes (41 KB) instead of building tiles; clip lengths of 3.5 to 6 s with dead lead-ins and `data-poster` at the end state. Determinism was good: `Motion.rand(seed)` everywhere, no `Math.random`.

**Second tier-3 run (178 planned cards) confirmed the three problems above on every card and added these.** The `runtime` field is wrong or aspirational on most cards: 43 of the 178 are tagged `webgl` and every one was rendered without WebGL (clip-path slices, rings and wedges, CSS 3D with `preserve-3d`, inline `feColorMatrix` filters, `mix-blend-mode`, conic and radial gradients, canvas 2D); the `css` cards are GSAP in practice; `canvas` cards render fine as SVG. Snippets lean on helpers that do not exist (`solveForceFixed`, `solveBeeswarmFixed`, `renderRingStages`, `rebinBySampleId`, `drawDensity`), on Three.js cameras and shader uniforms, on audio and video APIs that cannot exist in a frame (`split-edit` is `audio.play()` code, `time-compression` tweens `video.currentTime`), on `gsap.ticker` + scroll-event loops (`scroll-lag`), and on properties that are not transforms or not valid (`borderWidth`, `borderRadius` on the scene, a conic-gradient inside `clip-path`). Some recipes cannot do what they say: scaling a letter about its centre never fills the frame for a letter with a counter (`text-cutout-zoom`), `tracking-reveal` via `letter-spacing` and the variable-font cards via `font-variation-settings` reflow the line (fixed slot widths, per-glyph x, and the system font has a weight axis but no width or slant axis). Fixed timings (0.5 to 0.9 s moves, 3 s holds, 2 s cut spacing) would finish before the 1.2 s poster or sit still after it; every item got a return beat.

Renderer and gate findings new in this run, worth folding into the skill v2: the `tl.render` wrap alone did not re-run `renderAt` under the renderer in one case (`interval-expansion`); the proxy tween's `onUpdate` is what drives it, so keep both. GSAP's string interpolation of a long `polygon()` clip-path stalls in the renderer (frames hold the start state, then jump) while `inset()` tweens are fine: write the polygon from `renderAt`. A one-frame cut placed at exactly 1.00 s lands mid-blend on frame 30; place cuts between frame times. A global `const top` collides with `window.top` inside the harness wrapper (page error, the timeline never registers). CSS `stroke-dasharray` on a GSAP draw-on line is a lint error (`svg_drawon_css_dasharray_conflict`); SVG elements created without initial attributes log console errors in `check` when an attr tween first touches them; CSS class `fill`/`stroke` silently override attribute writes from `renderAt` (use inline style); a `<g>` inside `<clipPath>` is ignored. `check` reads `color: transparent` text as unpainted even with a text stroke (`text_not_painted`), so outline glyphs need a ground-coloured fill. Transform origins: a percentage `transform-origin` on a full-width clipped copy hinges at the stage edge, not the column edge; px offsets in `transform-origin` are not honoured reliably by the render path (use a clipping wrapper); GSAP's `transformOrigin` on SVG `<text>` and on needles is element-relative (use `svgOrigin` from `getBBox`); row-level `perspective` shears the end cards of a flap row (use per-card perspective); halves parked edge-on at 90 degrees stay visible as receding walls under perspective unless faded. Overlapping stacks need `data-layout-allow-overlap` and `-occlusion` on every covered text node, not the container.

### The HyperFrames rules (tier 1)

The recipes are sound as mechanisms, but their snippets would not pass HyperFrames' own gates as written. Worth folding into the skill v2:

- CSS `transform` on an element GSAP then tweens (`gsap_css_transform_conflict`, a lint error): `cursor-click-ripple` (`translate(-50%,-50%) scale(0)` on rings), `avatar-cloud-network`, `orbit-3d-entry`, `stat-bars-and-fills` (`scaleY(0)` in CSS), `css-marker-patterns`, `kinetic-beat-slam`'s metronome. Fix everywhere: position with left/top and set the from-state inside `fromTo`.
- Layout properties the contract forbids: `dynamic-content-sequencing` writes `style.width`, `ai-tracking-box` writes `left/top/width/height` per frame, `camera-cursor-tracking` tweens `maxWidth`, `reactive-displacement` writes `style.transform` strings in `onUpdate`. Rebuilt as scale/translate.
- Seek-safety is half-stated: most time-driven recipes rely on `onUpdate` alone, which the renderer skips when it seeks with events suppressed, and `dynamic-content-sequencing` / `control-target-sync` keep mutable `last*` trackers. Every time-driven frame here writes the DOM from a pure `renderAt(t)` and wraps `tl.render`, and lint then warns `gsap_repeated_fromto_without_baseline` on the proxy objects the camera and idle rules prescribe (harmless, but the canonical form always lints with a warning).
- Gates that bite the rules' own layouts: `scale-swap-transition`'s `inset: 0` cards trip `gsap_fullscreen_overlay_starts_visible` (error); stacked pixel-identical copies (`3d-text-depth-layers`, `chromatic-glitch`, `gradient-text-sweep`), the drag ghost and multi-cursor name tags trip `check`'s `content_overlap` unless the overlapping element itself carries `data-layout-allow-overlap` (the rules name `data-layout-allow-occlusion`, which the checker ignores; the attribute is not inherited by children).
- Recipes that do not do what they say: `avatar-cloud-network`'s dashed-line "draw" only marches dashes (needs an SVG mask with `maskUnits="userSpaceOnUse"`); `svg-path-draw`'s `dasharray = dashoffset = length` leaves a round-cap dot at the path start on frame 0 (park the boundary mid-gap: `dasharray "len len+20"`, offset `len+10`); `depth-scatter-assemble` spins the stage and never returns it, so its "resolve flat" constraint cannot hold; `split-tilt-cards`' CSS shadow direction contradicts its constraints; `gsap-effects`' typewriter depends on TextPlugin from a CDN and a CSS `@keyframes` blink, neither local nor timeline-driven.
- Values tuned for 60 fps and long shots: `waterfall-entry` hardcodes `F = 1/60`; `multi-cursor-choreography`'s beat grid and dwell rules need 4 s or more; `coordinate-target-zoom` gates on `document.fonts.ready` while `camera-cursor-tracking` forbids it. Minor: `card-morph-anchor`'s uniform-scale substitution scales the border and forces authoring the target content at 1/2.6 size, which is fragile.
- Determinism was clean: no `Math.random`, `Date.now` or `performance.now` anywhere in the 48 recipes; index-derived pseudo-random and baked schedules throughout.

Tier-1 compressions: the 3 s window is shorter than several rules' own timing tables (holds of 0.8 to 1 s, beat spacing of 1.2 to 1.8 s, climax dwell of 1 s or more), so those previews sit at the low end of their ranges and carry a quiet second beat so the clip never stands still. `dynamic-content-sequencing` shows three steps rather than the rule's three to six; `kinetic-beat-slam` runs its beat grid at 0.6 s. Pattern collections (`gsap-effects`, `css-marker-patterns`, `stat-bars-and-fills`, `cursor-drag`, `particle-burst`, `chromatic-glitch`, `gradient-text-sweep`, `anchored-layout-expand`, `motion-blur-streak`, `depth-of-field-blur`, `ambient-glow-bloom`) preview their most characteristic form, named in `one_line`.
