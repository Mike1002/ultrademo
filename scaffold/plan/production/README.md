# plan/production/ — the production step

The production step takes a confirmed plan (`plan.json` with its `direction` block and sketched scenes) and turns it into rendered scenes with their checks: one designer pass builds the kit for this product, then one frame builder per scene writes the scene as code over that kit, the scenes are assembled with the transitions the plan names, narration and the music bed are added, HyperFrames renders the whole video and every scene alone, the checks run on the rendered pixels and on the frames the renderer seeks before anyone looks (knowledge base §3: the checks run before you see anything, so review is for taste, not defects), and every scene with a hard failure gets one rebuild with its failures and stills before the user sees it.

## Run

From `scaffold/`:

```
node plan/production/run.mjs <project-dir> [--cap 5.00] [--only <scene-id>] [--model anthropic/claude-sonnet-5] [--parallel 4] [--fixtures <dir>] [--record <dir>] [--voice <spec>] [--no-fix]
```

`--no-fix` skips the fix round (step 7). Transitions are CSS by default; `ULTRADEMO_SHADERS=1` opts in to the GL shader transitions (off since 2026-10-29 until each shader is tested on a real seam).

`<project-dir>/plan.json` must validate (`plan/validate.mjs`) and every scene must be `sketched`. With `--only <scene-id>` only that scene (status `fix`, or still `sketched`) is rebuilt, re-rendered and re-checked, the kit and the other scenes are kept, and the whole video is assembled and rendered again. `--fixtures <dir>` replays recorded model answers (no paid call); `--record <dir>` records a live run so it can be replayed. The cap (`--cap`, default $5.00) stops the run before the next model call once reached, writes what exists, and says so in the report. The model key is `OPENROUTER_API_KEY` from the environment or `app/.env.local`; it is read, never printed or written.

Exit code 0 when every scene is `built`, 1 when any scene is `fix` or the run stopped.

## What it does, in order

1. **Validates** `plan.json` and the statuses. Copies what the frames reference into `<project>/assets/`: GSAP 3.15 from the motion gallery, the direction's fonts (the ones the direction step copied, else the open faces from the style gallery), the captured pages under `assets/scout/`, the music track under `assets/music/`.
2. **The designer pass** (`kit.mjs`): one Sonnet-class call with the direction block, the video style it is based on, the site's own tokens and words, the font files on disk, every scene's layout, content, visuals and copy, the sketch detail the user approved, the signature render from the direction page, and two captured pages as images. It writes `kit/tokens.css` (palette by role as literal `:root` variables, `@font-face` for the fetched open fonts, type roles `.t-display` `.t-text` `.t-mono` `.t-kicker` `.t-label` at video scale, spacing, radii, the ground treatment), `kit/components.css` + `kit/components.html` (the rebuilt parts every scene may use: card, pill, button, counter, list row, device frame, panel, kicker, cursor, plus the product-specific parts the plan names, with the product's real labels), and `kit/README.md` (what exists and how to use it). The kit is linted through a sheet frame (`compositions/frames/kit-sheet.html`); a parse or lint problem costs one repair call. A still of the sheet lands at `kit/sheet.jpg`.
3. **The frame builders** (`frames.mjs`): one call per scene, up to `--parallel` (4) at once. Each prompt carries the frame contract and the motion doctrine (`craft.mjs`), the direction, the scene's full spec (the motion lines across the whole duration, the carry in and out, the reading windows, the word cap, the numbers allowed), the assets it may place with their pixel sizes (captured visuals are placed from `assets/scout/`, never redrawn), the kit (README, both CSS files, the markup library), the named shot blueprint sliced from HyperFrames' blueprint file (intent, the roles-served lines for this role, duration, shot structure, rule mapping; ours from D-49), the gate-clean `frame.html` of each motion style the scene names (from the motion gallery, D-57), the approved signature render for the signature moment, and the renderer traps list read from the motion gallery README. The answer is a `<template>` sub-composition; the pipeline inlines the kit CSS as the template's first `<style>`, stamps the root attributes and the timeline key, writes `compositions/frames/<id>.html`, mounts it alone in a scratch host (`production/build/<id>/`), runs `hyperframes lint`, loads it in a headless browser to catch runtime errors lint cannot see (an invalid selector, an undefined name; without this a broken frame costs a 45 s wait in the renderer) and reads the timeline length, then `hyperframes check --no-contrast`. A lint error, a runtime error or a timeline that stops short of the scene gets one repair call with the findings quoted; what still fails is recorded plainly. Prompts, answers, lint and check output are kept under `production/frames/`.
4. **Assembly** (`assemble.mjs`): `index.html` mounts every built scene as a sub-composition clip at its plan start on its own rising track (the incoming scene composites on top), extends an outgoing scene by `direction.transition_overlap_s` (0.4 s by default) when the next scene's `transition_in` overlaps, and stamps the transition on the master timeline: `crossfade`, `zoom-through`, `wipe`; `cut` and `match` are hard cuts whose carry element makes the join. **GL shader transitions**: `@hyperframes/shader-transitions` 0.8.145 (pinned exactly in `scaffold/package.json`; Apache-2.0 in its LICENSE file, though the npm metadata reads "Proprietary" because its package.json has no licence field; one dependency, html2canvas 1.4.1, MIT) is installed, so its IIFE build is copied to `assets/shader-transitions.js` and `HyperShader.init()` takes every boundary on the master timeline. Under the renderer (virtual time) the package composites per frame on the page; verified on the Orbit run, where the crossfades render as shader morphs. The whitelist (`SHADER_WHITELIST`, ten): `cross-warp-morph`, `domain-warp` (dissolves), `whip-pan` (directional push), `cinematic-zoom`, `gravitational-lens` (zoom-through), `sdf-iris` (wipe), `light-leak`, `flash-through-white` (light), `chromatic-split`, `ripple-waves`; left out as too loud for a product: `ridged-burn`, `glitch`, `swirl-vortex`, `thermal-distortion`. The mapping (`shaderFor`): a crossfade takes one primary per energy (`cross-warp-morph` calm and steady, `whip-pan` high) and one accent into the proof scene (`light-leak`, or `cinematic-zoom` at high energy); zoom-through is `cinematic-zoom`; a wipe is `sdf-iris` (`whip-pan` at high energy); cuts and match cuts are near-instant swaps. When the package does not resolve (or `ULTRADEMO_SHADERS=0`) every transition is CSS on the clip wrappers as before. Each frame root's `data-duration` is set to its clip length so no sub-composition blanks under the overlap. Narration (when `video.narration` is `voice` or `hybrid`) is generated per sentence through `scaffold/tts` with the direction's voice (`pocket:<name>` for the free tier, `chatterbox` for expressive, `elevenlabs` or any `provider:spec`, `--voice` or `ULTRADEMO_VOICE` to override), aligned for word timings when the align environment exists, placed at each scene's start, and mounted as `<audio>` beside the bed for the Studio preview. A scene that failed to build is left out of the assembly and the following scenes close up, so the video still renders; its checks say why it is missing.
5. **Renders** (`render.mjs`): every scene alone from its scratch host to `out/scenes/<id>.mp4` (two at a time), the whole video to `out/video-render.mp4`, then the ffmpeg mix to `out/video.mp4` (`audio.mjs`): the bed starts at the track's usable-from offset from `scaffold/music/curated.json` (or the "bed starts at N s" note in the plan's track line), loops to the length, fades in 1.2 s and out 2 s, ducks under the voice with the v1 sidechain (threshold 0.02, ratio 4, attack 60 ms, release 900 ms), and the programme is mastered to **−14 LUFS** with a **−1 dBTP** true-peak limit in two `loudnorm` passes (the v1 chain at −16 LUFS, retargeted). Event-frame stills per scene (first frame, every motion-line boundary, last frame) go to `out/stills/` and a six-per-row sheet to `out/sheet.jpg`.
6. **Checks** (`checks.mjs`) on the renders, to `out/checks.json` and `out/checks.md` in plain words per scene. Pixel measures reuse `scaffold/scripts/lib/frames.mjs` (15 fps, 240×135 grey): **motion per second** is the mean grey change between consecutive samples, **still time** the share of one-second windows where nothing visibly happened, **longest still** the longest run of samples with no change at all. For scale: a one-shot measures 2.70 motion per second and 0.3% still time with this code, the beat-kit video 9.7%. DOM probes open every scene's frame in a headless browser (`production/probe/<id>.html`), seek its timeline to frame 0, every motion-line boundary, the end of each reading window and the last frame, and read what is visible: the headline's words (frame-0 copy on the first scene; copy readable through `reads[].to_s`), every text box against the 1920×1080 canvas (overlays inside their boxes), every number on screen against the plan's numbers and claims (the claims check; a value the site itself shows is a note, a count under ten is information), and the carried element on both sides of each seam (by its words when it has any, else by the accent colour's presence on the last and first frames; otherwise "by eye"). Also: nothing moving at the end of a scene (the last sample before the cut, under `MOVING_TOL`), words per second on screen against the measured band, the copy cap and the wrap heuristic, the render's frame count, loudness and true peak of the final mix.
   **Composition checks (D-67, `composition.mjs`)**, on the frames the renderer seeks, not on the code. The DOM layer opens every scene's frame headless, seeks it every 0.25 s (plus its motion-line boundaries and the 0.4 s overlap after its end), and reads every visible element's box: text runs, images and SVG, painted containers (a background, a border or a shadow, at least 60×34 px; layers marked `data-decor`, the cursor, anything blurred past 8 px or covering 70% of the frame are left out). Boxes closer than 22 px merge into blocks, what a viewer reads as one thing. Then, per sample: (1) every visible container has content: a descendant text, image or painted part, or a text or image drawn at least 85% inside it (an empty card, a ghost outline or a placeholder fails); (2) balance: the primary blocks (the brand mark and placed labels aside) cover at least 30% of the frame's width or height and 5% of its area, and their centre of mass, on a 48×27 occupancy grid so nested boxes count once, sits in the middle third unless the scene's layout names that side, a split or a corner; content in a corner ninth is "anchored in the corner"; (3) where the layout says centred (and names no side), or a scene has one primary block, every primary block is centred horizontally within 2% (38 px); (4) nothing within 4% of an edge (77 px, 43 px) but the brand mark and labels the layout places there (`data-edge`, `data-brand`), blocks covering 45% of the frame aside; a small block more than 22% of the frame width from everything else in the outer band "floats alone" (the brand mark too, unless the layout puts it at an edge); (5) transitions: the outgoing scene's tail and the incoming scene's head are modelled through the transition (a crossfade's power2.inOut opacity, zoom-through's scale about the centre, a wipe's clip), and an outgoing block still at 30% or more over an incoming block already at 30% or more, overlapping by a fifth of the smaller box, is a collision (the same words on both sides, the carry, are exempt; shader transitions blend like a crossfade); (6) scale: the headline at its largest at least 90% of the direction's smallest headline size (`direction.type.display.sizes`, 64 px when none), and on a product moment (a captured or rebuilt product part; not a logo, a line of copy, the button, or the close) the widest product block at least 40% of the frame width. A fault must last 0.5 s (an empty box) or 0.75 s (the rest) to count, so an entrance passing through a corner is not one. Every failure is a sentence with the scene, the time in the video and the element ("02-one-link at 0:05.5–0:10.2 (0.05–4.72 s into the scene): the content is anchored in the top-left corner (its centre at 16% across, 24% down, covering 14% of the frame) with the rest of the frame empty"). On the first Orbit run the checks name all six faults the review found: the empty box near 0:03 (measured from 0:04.3 at 85% opacity), the corner-anchored card at 0:05, the empty box at 0:24, the Start free button 78 px right of centre from 0:25.6, the Orbit mark alone at the right edge from 0:28.3, and the 03→04 crossfade collision. A transition collision is a hard failure of the outgoing scene and a note on the incoming one. The pixel layer (`pixelComposition`) reads any video from an edge map at 2 frames per second (where the ink sits, its box, corner and edge shares); it runs on the whole video as a note, and it is what the comparisons use for reference videos, which have no DOM.
   Targets: for Launch, D-43 (still time 0%, motion per second ≥ 2.5, longest still < 0.5 s); for the other templates the direction's pace band; words per second from `research/reference-videos/tools/bands-by-template.json` where a band exists. **Hard checks** send a scene to `fix` with the reason: not built, lint errors after the repair, no render, a static clip, a dead hold over 1 s, copy over its cap, the headline missing from frame 0 (first scene), copy leaving before its reading window ends, text outside the canvas, a number not in the plan, and every composition failure. Everything else is a note for the review page. `scenes[].measured` and `status` are written back into `plan.json`; nothing else in the plan changes (rule 13 of the plan module). Stills of the whole video at the middle of every overlapping transition go to `out/stills/seam-*.jpg`.
7. **The fix round**: every scene with a hard failure (other than copy over its cap, which is the plan's to fix) gets one rebuild call (`fix:<id>`, step `fix` in the ledger) carrying the plan, the kit and the builder doctrine as before, plus the failures in plain words, up to four stills of its render at the failure times (960 px) and the previous file. The rebuild is linted, run in the browser and checked like a first build (one lint repair, `fix-repair:<id>`); a rebuild that does not pass keeps the round-1 frame (kept as `production/frames/<id>.round1.html`). Then the index is reassembled, the rebuilt scenes and the whole video re-rendered, and every check runs again (round 2). At most two rounds per scene. Round 1 is kept as `out/checks-round1.json` and `.md`; the report shows both rounds per scene. The cap applies: a fix call that would pass it is skipped and the report says so. In a replayed run without recorded fix answers the round says "no recorded answer" and keeps round 1.
8. **Time and tokens** to `out/cost.json`: every call with its tokens, dollars and seconds (OpenRouter's usage field), per step and per scene, the wall time per step, the cap, and whether the run stopped at it. A replayed call costs $0 and keeps the recorded cost and seconds beside it.
9. **The report** `out/report.md`: what was built, the whole video's numbers against the targets, one row per scene (with its composition result), both rounds, cost and wall time against the D-62 working targets (first draft under 8 minutes for a 20–30 s video, under 15 minutes for 45–60 s; provisional, never a gate), and what the review page shows next.

## Files

| File | What it does |
|---|---|
| `run.mjs` | The CLI and `runProduction(args, opts)`; `parseArgs`, `prepareAssets`. |
| `model.mjs` | `callText` (OpenRouter, text answers, the call name in a header), `recordedFetch` / `recordingFetch` keyed by call name, `imageOf`; `Ledger`, `CapReached`, `loadKey` re-exported from `plan/direction/propose.mjs` so one accounting rule holds. |
| `composition.mjs` | The composition checks: `COMPOSITION_SCRIPT` (the in-page box reader), `probeComposition`, `blocksOf`, `measureSample`, `layoutIntent`, `sampleFailures`, `persistentFailures`, `sceneComposition`, `transitionModel`, `transitionCollisions`, `headlineMinPx`, `isProductMoment`, and the pixel layer `frameInk`, `pixelComposition`. |
| `craft.mjs` | The frame contract, the motion doctrine and the compose-for-video rules with the composition checks in plain words (`COMPOSITION`) as prompt text, `rendererTraps()` (read from the motion gallery README), `blueprintText(id, role)`, `galleryCode(id)`, `sceneRuleIds`, `openFonts`, `styleDefinition`, the paths. |
| `kit.mjs` | `designerPrompt`, `parseFiles` (the `<<<FILE path>>>` markers), `kitProblems`, `writeKit`, `kitCss`, `kitSheetFrame`, `designerPass`. |
| `frames.mjs` | `builderPrompt` (with `fix`, the rebuild prompt), `fixSection`, `parseFrame`, `finishFrame`, `idPrefix`, `runtimeProbe`, `scratchHost`, `hostHtml`, `lintProject`, `checkProject`, `buildScene`, `parallel`, `setFrameDuration`. |
| `assemble.mjs` | `clipPlan`, `transitionGsap`, `assembleIndex`, `shaderTransitionsAvailable`, `shaderBundle`, `SHADER_WHITELIST`, `shaderFor`. |
| `render.mjs` | `renderProject`, `probeVideo`, `eventTimes`, `still`, `sceneStills`, `frameSheet`, `probePage`. |
| `audio.mjs` | `musicFor`, `voiceSpec`, `narrate`, `mixAudio`, `measureLoudness`. |
| `checks.mjs` | `targetsFor`, `motionStats`, `colourShare`, `numberTokens`, `probeScenes`, `compositionFindings`, `runChecks`, `applyToPlan`, `checksMarkdown`. |
| `report.mjs` | `reportMarkdown`, `draftTarget`. |

What a run writes under `<project-dir>`: `kit/`, `compositions/frames/<id>.html` (+ `kit-sheet.html`), `assets/` (gsap, fonts, scout, music, voice), `index.html`, `hyperframes.json`, `production/` (prompts, answers, lint and check output, the scratch hosts, the probe pages), `out/` (`video.mp4`, `video-render.mp4` before the mix, `scenes/<id>.mp4`, `stills/`, `sheet.jpg`, `checks.json`, `checks.md`, `cost.json`, `mix.json`, `report.md`).
